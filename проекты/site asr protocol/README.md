# ПротоСов

Веб-сервис для загрузки аудио/видео встреч, транскрибации с разделением по спикерам и формирования протокола.

## Возможности

- Загрузка файлов: `mp4`, `mkv`, `avi`, `mov`, `webm`, `mp3`, `wav`
- Транскрибация с диаризацией через WhisperX
- Протокол встречи (краткая выжимка, пересказ, таймлайн по блокам)
- Редактирование транскрибации, переименование спикеров, экспорт в Markdown
- Совместный доступ к файлам (просмотр / редактирование)

## Стек
| Компонент    | Назначение                                     |
| ------------ | ---------------------------------------------- |
| Django       | Веб-приложение, API                            |
| PostgreSQL   | Основная БД                                    |
| Redis        | Брокер и backend Celery, Redis lock GigaChat   |
| Celery       | Фоновые задачи (транскрибация, протокол)       |
| WhisperX     | Распознавание речи + выравнивание + диаризация |
| GigaChat API | Генерация протокола (модель GigaChat-Pro)      |
| FFmpeg       | Определение длительности медиафайлов           |

## Установка

### Системные зависимости
- **Python** 3.10+ (рекомендуется 3.11)
- **PostgreSQL**
- **Redis** 
- **FFmpeg** (используется для определения длительности медиафайлов)

### Python-зависимости
```bash
pip install django psycopg2-binary celery redis python-dotenv whisperx torch torchaudio gigachat markdown
```

### Модели машинного обучения
Скачиваются автоматически при первом запуске задачи:
- **WhisperX** - модель `large-v2`, устройство `cpu`
  
  Для запуска на GPU установите PyTorch с поддержкой CUDA и задайте `device="cuda"`, `compute_type="float16"`, `batch_size=16` в файле `config/main/transcribe_worker.py` (в классе TranscribeConfig).

## Файл `.env`

Создайте `.env` в корне проекта (рядом с `manage.py`, каталог `config/`):

```env
HF_KEY=токен           # диаризация (pyannote)
GIGA_KEY=токен            # протоколирование

REDIS_URL=redis://localhost:6379/0
```

## Запуск

```bash
# Терминал 1 - сайт
python manage.py runserver

# Терминал 2 - фоновые задачи
python -m celery -A config worker --loglevel=info
```

## Создание нового пользователя
(В БД присутствует пользователь user с паролем user)

**Через Django Admin (обычный пользователь):**

1. Запустите сервер: `python manage.py runserver`
2. Откройте `http://localhost:8000/admin/` и войдите под суперпользователем
3. В разделе **Login** нажмите **Users → Add user**
4. Заполните поля **Login** и **Password**, нажмите **Save**
5. При необходимости задайте роль: `u` - пользователь, `a` - администратор, `ua` - оба
6. Новый пользователь может сразу войти через `/auth/`

**Через консоль:**

```bash
python manage.py createsuperuser
```

## Параллельность

- **WhisperX** (по умолчанию 4) - 4 транскрибаций одновременно; каждый слот держит свою копию модели в RAM
- **GigaChat** - один запрос одновременно

## Очистка БД

Полное удаление всех записей из всех таблиц:

```bash
python manage.py flush --no-input
```

Файлы в `media/` команда не удаляет - очищайте вручную.

## Структура каталогов

```
config/                 
  config/               # settings.py, celery.py
  main/                 # основная логика, задачи, transcribe_worker.py
```

## Маршруты

Обозначения в столбце **Роль**:

- **u** — пользователь (`role=u` или `ua`)
- **a** — администратор сервиса (`role=a` или `ua`, либо `is_staff` / `is_superuser`)
- **S** — система (фоновые задачи Celery от имени пользователя)
- **просмотр** / **редактирование** — доступ к конкретной транскрибации или файлу (владелец или выданный доступ)
